## 1. 概述

### 1.1 三种工具类型

StaffStudio 支持三种工具协议，覆盖从简单 API 调用到跨 Agent 协作的完整场景：

| 类型 | 协议 | 典型场景 | 特点 |
|------|------|----------|------|
| **HTTP** | REST API | 调用内部/外部 HTTP 服务 | 最简单直接，支持 GET/POST/PUT/PATCH/DELETE |
| **MCP** | Model Context Protocol | 连接标准化 AI 工具服务器 | 支持 stdio/HTTP/SSE 三种传输，支持分页发现 |
| **A2A** | Agent-to-Agent | 跨 Agent 任务委派 | 持久化 Task 生命周期，支持流式、恢复、取消 |

### 1.2 架构全景

```
                    ┌────────────────────────────────────────────────┐
                    │              Harness Agent Loop                 │
                    │                                                │
                    │  HarnessCapabilityInvoker                      │

                    │    ├── 能力展开 (describe → activate)           │
```

## 2. ToolExecutor 架构

### 2.1 执行入口

`ToolExecutor.execute()` 是所有工具调用的统一入口：

```python
# backend/app/tools/tool_executor.py
class ToolExecutor:
    def __init__(self, db: Session):
        self.db = db
        self.settings = get_settings()

    def execute(
        self,
        tenant_id: str,
        tool_call: ToolCall,
        active_skill_id: str | None = None,

        session_id: str | None = None,
        invocation_id: str | None = None,
        timeout_seconds_override: float | None = None,
    ) -> ToolResult:
```

### 2.2 四层前置检查

每次调用前，系统执行四层安全检查：

```python
# 第 1 层：工具是否存在
tool = self.db.exec(
    select(Tool).where(Tool.tenant_id == tenant_id, Tool.name == tool_call.name)
).first()
if not tool:
    return self._error(tool_call.name, "NOT_FOUND", "工具不存在或未配置。")

# 第 2 层：工具是否启用
if not tool.enabled:
    return self._error(tool.name, "DISABLED", "工具当前未启用。")

# 第 3 层：Agent 是否有权访问
if agent_id and tool.id not in {
    row.id for row in visible_tool_rows(self.db, tenant_id, agent_id, include_inactive=False)
}:
    return self._error(tool.name, "NOT_ALLOWED", "当前员工未启用该工具。")

# 第 4 层：当前技能是否允许
if (
    active_skill_id
    and tool.allowed_skills_json
    and active_skill_id not in tool.allowed_skills_json
):
    return self._error(tool.name, "NOT_ALLOWED", "当前技能不允许调用该工具。")
```

### 2.3 协议路由

通过前置检查后，根据 `tool_type` 路由到对应的执行逻辑：

```python
if (tool.tool_type or "http") == "mcp":
    return self._execute_mcp_tool(tool, tool_call.arguments, ...)
if (tool.tool_type or "http") == "a2a":
    return self._execute_a2a_tool(tool, tool_call.arguments, ...)
if (tool.tool_type or "http") != "http":
    return self._error(tool.name, "UNSUPPORTED_TOOL_TYPE", f"不支持的工具类型：{tool.tool_type}")

# 默认：HTTP 执行
return self._execute_http_tool(tool, tool_call.arguments, ...)
```

## 3. HTTP 工具

### 3.1 执行流程

HTTP 工具是最直接的工具类型，通过 `httpx` 发起 HTTP 请求：

```python
# 准备请求头（含认证信息）
headers = self._request_headers(
    tool.url,
    self._resolve_headers(tool.headers_json or {}, tool.auth_json or {}),
)

# 执行策略（超时等）
policy = self._execution_policy(tool, timeout_seconds_override=timeout_seconds_override)

try:
    with httpx.Client(timeout=policy.timeout_seconds) as client:
        if tool.method.upper() == "GET":
            # GET 请求：参数转为 query string
            request_url, request_kwargs = prepare_get_request(tool.url, tool_call.arguments)
            response = client.request(tool.method.upper(), request_url, headers=headers, **request_kwargs)
        else:
            # 其他方法：参数作为 JSON body
            response = client.request(tool.method.upper(), tool.url, headers=headers, json=tool_call.arguments)
        response.raise_for_status()
        return ToolResult(tool_name=tool.name, success=True, data=self._response_data(response), error=None)
except httpx.TimeoutException:
    return self._error(tool.name, "TIMEOUT", f"工具调用超过 {policy.timeout_seconds:g} 秒未返回。")
except httpx.HTTPStatusError as exc:
    return self._error(tool.name, "HTTP_ERROR", f"工具返回异常状态码：{exc.response.status_code}")
except Exception as exc:
    return self._error(tool.name, "EXECUTION_ERROR", str(exc))
```

### 3.2 GET 请求参数处理

```python
# backend/app/tools/http_request.py
def prepare_get_request(url: str, params: dict[str, Any]) -> tuple[str, dict[str, Any]]:
    clean_params = {str(key): value for key, value in (params or {}).items() if value is not None}
    if not clean_params:
        return url, {}

    parsed = urlsplit(url)
    if not parsed.query:
        # URL 没有现有 query，直接用 httpx 的 params 参数
        return url, {"params": clean_params}

    # URL 已有 query，合并参数
    merged_params: dict[str, Any] = dict(parse_qsl(parsed.query, keep_blank_values=True))
    merged_params.update(clean_params)
    merged_url = urlunsplit((
        parsed.scheme, parsed.netloc, parsed.path,
        urlencode(merged_params, doseq=True), parsed.fragment,
    ))
    return merged_url, {}
```

### 3.3 认证解析

系统支持三种认证方式：

```python
def _resolve_headers(self, headers: dict[str, Any], auth: dict[str, Any]) -> dict[str, str]:
    resolved = {key: self._resolve_secret(str(value)) for key, value in headers.items()}
    auth_type = str(auth.get("type") or "").strip().lower()

    if auth_type == "bearer" and auth.get("token"):
        # Bearer Token
        resolved["Authorization"] = f"Bearer {self._resolve_secret(str(auth['token']))}"

    elif auth_type == "basic" and "Authorization" not in resolved:
        # Basic Auth
        basic = auth.get("basic")
        username = self._resolve_secret(str(basic["username"]))
        password = self._resolve_secret(str(basic["password"]))
        credentials = base64.b64encode(f"{username}:{password}".encode()).decode("ascii")
        resolved["Authorization"] = f"Basic {credentials}"

    elif auth_type not in {"bearer", "basic"}:
        # 自定义 Header（如 X-API-Key）
        for key, value in auth.items():
            if key == "type" or value is None:
                continue
            resolved[str(key)] = self._resolve_secret(str(value))

    return resolved
```

### 3.4 Secret 插值

工具配置中可以使用 `${secret.NAME}` 模式引用环境变量中的密钥：

```python
SECRET_PATTERN = re.compile(r"\$\{secret\.([A-Z0-9_]+)\}")

def _resolve_secret(self, value: str) -> str:
    def repl(match: re.Match[str]) -> str:
        return os.getenv(match.group(1), "")
    return SECRET_PATTERN.sub(repl, value)
```

例如，配置 `Authorization: Bearer ${secret.API_TOKEN}` 会在运行时从环境变量读取 `API_TOKEN` 的值。

> **安全要点**：Secret 只从环境变量读取，不会从数据库或用户输入中获取。

## 4. MCP 工具

### 4.1 Model Context Protocol 简介

MCP 是一个标准化的 AI 工具协议，类似于 USB 接口——不同厂商的工具服务器只要遵循 MCP 协议，就能被 Agent 统一调用。

### 4.2 四种传输方式

```python
# backend/app/tools/mcp_client.py
def normalize_transport(config: dict[str, Any]) -> str:
    raw = str(config.get("transport") or "").strip().lower()
    if raw == "streamable_http":
        return "http"
    if raw:
        return raw
    # 根据配置推断
    if config.get("command"):
        return "stdio"       # 本地进程通信
    if config.get("url"):
        return "http"        # HTTP 流式通信
    return "builtin"         # 内置演示
```

| 传输方式 | 说明 | 适用场景 |
|----------|------|----------|
| `streamable_http` | HTTP POST + JSON-RPC，支持 SSE 响应 | 远程 MCP 服务器（推荐） |
| `sse` | GET 建立 SSE 流 + POST 发送请求 | 旧版 MCP 服务器 |
| `stdio` | 启动本地进程，通过 stdin/stdout 通信 | 本地工具（如 Node.js 脚本） |
| `builtin` | 内置演示服务器 | 开发测试 |

### 4.3 MCP 会话生命周期

每次 MCP 调用都遵循 JSON-RPC 会话模式：

```
┌──────────┐                          ┌──────────────┐
│  Client   │                          │  MCP Server   │
└─────┬────┘                          └──────┬───────┘
      │                                      │
      │  1. initialize (握手)                │
      │──────────────────────────────────────►│
      │◄──────────────────────────────────────│
      │  2. notifications/initialized (确认)  │
      │──────────────────────────────────────►│
      │                                      │
      │  3. tools/list (发现工具)             │
      │──────────────────────────────────────►│
      │◄──────────────────────────────────────│
      │  工具列表（支持分页）                  │
      │                                      │
      │  4. tools/call (调用工具)             │
      │──────────────────────────────────────►│
      │◄──────────────────────────────────────│
      │  工具执行结果                          │
      │                                      │
```

### 4.4 核心实现

```python
# backend/app/tools/mcp_client.py
class _MCPSession:
    """MCP JSON-RPC 会话基类。"""

    def call_tool_envelope(self, name: str, arguments: dict[str, Any]) -> dict[str, Any]:
        with self:                     # 建立连接
            self._initialize()         # 握手
            result = self._request(
                "tools/call",
                {"name": name, "arguments": arguments},
            )
            return _tool_result_envelope(result)

    def _list_all_pages(self, method: str, result_key: str) -> list[dict[str, Any]]:
        """支持游标分页的工具发现。"""
        items = []
        cursor = None
        seen_cursors = set()
        while True:
            params = {"cursor": cursor} if cursor is not None else {}
            result = self._request(method, params)
            items.extend(item for item in (result.get(result_key) or []) if isinstance(item, dict))

            raw_cursor = result.get("nextCursor") or result.get("next_cursor")
            next_cursor = str(raw_cursor).strip() if raw_cursor is not None else ""
            if not next_cursor:
                return items
            if next_cursor in seen_cursors:
                raise MCPClientError(f"MCP {method} 返回了重复分页游标：{next_cursor}")
            seen_cursors.add(next_cursor)
            cursor = next_cursor
```

### 4.5 stdio 传输

stdio 传输启动一个本地子进程，通过 stdin/stdout 进行 JSON-RPC 通信：

```python
class _StdioSession(_MCPSession):
    def __enter__(self):
        command = _stdio_command(self.config)
        env = os.environ.copy()
        # 合并自定义环境变量
        if isinstance(self.config.get("env"), Mapping):
            env.update({str(k): str(v) for k, v in self.config["env"].items()})

        # 启动受控进程
        self._managed_process = ManagedProcess.start(
            command, cwd=cwd, env=env,
            stdin=subprocess.PIPE, stdout=subprocess.PIPE, stderr=subprocess.PIPE,
            text=True, encoding="utf-8",
        )
        self._proc = self._managed_process.process
        self._stdout_reader = _PipeReader(self._proc.stdout)
        self._stderr_collector = _StderrCollector(self._proc.stderr)
        return self

    def _request(self, method: str, params: dict[str, Any]) -> Any:
        self._next_id += 1
        request_id = self._next_id
        # 发送 JSON-RPC 请求
        _send_json(self._proc, {
            "jsonrpc": "2.0", "id": request_id,
            "method": method, "params": params,
        }, timeout_seconds=self.timeout_seconds)
        # 等待匹配的响应
        response = _read_response(
            self._proc, self._stdout_reader,
            expected_id=request_id,
            timeout_seconds=...,
            stderr=self._stderr_collector,
        )
        return response.get("result")
```

## 5. A2A 工具

### 5.1 Agent-to-Agent 协议简介

A2A 协议用于 Agent 之间的任务委派。与 HTTP 工具不同，A2A 任务有**持久化的生命周期**：

```
┌──────────┐                              ┌──────────────┐
│  Client   │                              │  Remote Agent │
│  Agent    │                              │  (A2A Server) │
└─────┬────┘                              └──────┬───────┘
      │                                          │
      │  1. 发现 Agent Card                      │
      │──────────────────────────────────────────►│
      │  GET /.well-known/agent-card.json         │
      │◄──────────────────────────────────────────│
      │                                          │
      │  2. SendMessage / SendStreamingMessage    │
      │──────────────────────────────────────────►│
      │◄──────────────────────────────────────────│
      │  Task {id, status: "working"}             │
      │                                          │
      │  3. SubscribeToTask / GetTask (轮询)      │
      │──────────────────────────────────────────►│
      │◄──────────────────────────────────────────│
      │  Task {status: "completed", artifacts}    │
      │                                          │
```

### 5.2 Task 状态机

```
                    submitted
                       │
                       ▼
    ┌─────────── working ───────────┐
    │               │               │
    ▼               ▼               ▼
 completed     input-required    failed
               (等待用户输入)
                    │
                    ▼
               (继续 working)

    其他终态：canceled, rejected
```

```python
_TERMINAL_STATES = {"completed", "failed", "canceled", "cancelled", "rejected"}
_INTERRUPTED_STATES = {"input-required", "auth-required"}
```

### 5.3 A2AClient 核心实现

```python
# backend/app/tools/a2a_client.py
class A2AClient:
    def execute(self, arguments: dict[str, Any]) -> dict[str, Any]:
        lock_key = self._invocation_lock_key()
        with _run_lock(lock_key):         # 防止并发重复调用
            return self._execute_locked(arguments)

    def _execute_locked(self, arguments: dict[str, Any]) -> dict[str, Any]:
        # 1. 检查是否有已存在的调用（恢复场景）
        existing = self._existing_invocation()
        if existing is not None:
            return self._resume_existing(existing)

        # 2. 发现远程 Agent
        self._discover_agent()

        # 3. 构建消息
        continuation = self._continuation(arguments)
        message = self._message(arguments, continuation)

        # 4. 持久化调用记录
        run = A2ATaskRun(
            direction="client",
            tenant_id=self.tool.tenant_id,
            tool_id=self.tool.id,
            status="submitted",
            request_json={"arguments": arguments, "message": message},
            ...
        )
        self.db.add(run)
        self.db.commit()

        # 5. 发送并等待完成
        deadline = time.monotonic() + self.timeout_seconds
        result = self._send(run, message, deadline=deadline)
        return self._finalize(run, result)
```

### 5.4 流式支持

A2A 支持 SSE 流式传输：

```python
def _stream_method(self, run, method, params, *, deadline):
    payload = self._payload(method, params)
    headers = dict(self.headers)
    headers["Accept"] = "text/event-stream"
    if run.last_event_id:
        headers["Last-Event-ID"] = run.last_event_id  # 断点续传

    with httpx.Client(timeout=timeout) as client:
        with client.stream("POST", self.endpoint_url, headers=headers, json=payload) as response:
            for event_id, data in _iter_sse(response.iter_lines()):
                envelope = json.loads(data)
                result = envelope.get("result")
                if not isinstance(result, dict):
                    continue
                run.last_event_id = event_id or run.last_event_id
                task = _task_from_event(result)
                if task is not None:
                    accumulated_task = _merge_task(accumulated_task, task)
                    if _task_state(task) in _TERMINAL_STATES | _INTERRUPTED_STATES:
                        return accumulated_task
    return accumulated_task or last
```

### 5.6 Agent Card 发现

A2A 客户端会自动发现远程 Agent 的能力描述：

```python
def _discover_agent(self) -> None:
    card_url = self._agent_card_url()  # 默认 /.well-known/agent-card.json
    with httpx.Client(timeout=min(self.timeout_seconds, 15.0)) as client:
        response = client.get(card_url, headers=self.headers)
        card = response.json()
    self.agent_card = card

    # 从 Agent Card 中选择 JSONRPC 接口
    interfaces = card.get("supportedInterfaces") or card.get("supported_interfaces")
    if isinstance(interfaces, list):
        selected = next(
            item for item in interfaces
            if str(item.get("protocolBinding") or "").upper() in {"JSONRPC", "JSON-RPC"}
            and str(item.get("url") or "").strip()
        )
        if selected:
            self.endpoint_url = str(selected["url"]).strip()
            self.protocol_version = str(selected.get("protocolVersion") or self.protocol_version)
```

## 6. HarnessCapabilityInvoker

### 6.1 定位

`HarnessCapabilityInvoker` 是 Harness Agent Loop 和工具系统之间的桥梁。它不直接执行工具，而是：

1. **管理能力的发现与激活**（渐进式披露）
2. **在每次调用前重新检查授权**
3. **防止重复的副作用调用**（逻辑动作回放）
4. **持久化大型结果**（避免撑爆模型上下文）

### 6.2 渐进式披露

Harness 采用"目录 → 展开 → 激活 → 调用"的四步模式：

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   catalog     │───►│   describe   │───►│   activate   │───►│    invoke    │
│              │    │              │    │              │    │              │
│ 列出所有可用  │    │ 加载完整     │    │ 加入已激活   │    │ 实际执行     │
│ 能力的摘要   │    │ schema       │    │ 集合         │    │ 工具调用     │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
   capability_search   capability_describe    (内部状态)        具体工具
```

```python
# 第 1 步：搜索能力目录
def _search_capabilities(self, arguments):
    query = str(arguments.get("query") or "").strip()
    matches = search_capability_descriptors(self._descriptors.values(), query, ...)
    return {
        "success": True,
        "data": {
            "matches": [catalog_entry(item).model_dump(mode="json") for item in matches],
            "notice": "搜索结果仍未激活；选择后调用 capability_describe 加载完整 schema。",
        },
    }

# 第 2 步：展开并激活
def _describe_capabilities(self, arguments):
    refs = [str(item).strip() for item in arguments.get("capabilities")]
    for ref in refs:
        descriptor = by_ref.get(ref)
        if self._currently_authorized_descriptor(descriptor) is None:
            revoked.append(ref)
            continue
        activated.append(model_descriptor(descriptor).model_dump(mode="json"))
        self._activated_names.add(descriptor.name)  # 激活！
    return {"success": True, "data": {"activated_capabilities": activated}}

# 第 3 步：调用（检查是否已激活）
def invoke(self, name, arguments):
    descriptor = self._descriptors.get(name)
    if name not in self._activated_names:
        return _failure("CAPABILITY_NOT_ACTIVATED", "请先调用 capability_describe。")
    # ... 执行调用
```

### 6.3 授权再检查

每次调用前，系统会重新构建当前的授权清单，确保能力没有被中途撤权：

```python
def _currently_authorized_descriptor(self, frozen: CapabilityDescriptor) -> CapabilityDescriptor | None:
    # 重新构建当前时刻的授权清单
    current = CapabilityManifestBuilder(self.db).build(
        self.tenant_id, self.agent_id, self.active_skill, self.active_step_id,
    )
    # 在最新清单中查找匹配的能力
    return next(
        item for item in current.available
        if item.available
        and item.capability_id == frozen.capability_id
        and item.name == frozen.name
        and item.kind == frozen.kind
    )
```

```python
def invoke(self, name, arguments):
    # ... 前置检查 ...
    if descriptor.kind == "internal":
        result = self._invoke_internal(name, arguments)      # 内部能力
    elif descriptor.kind == "file":
        result = self._invoke_file(name, arguments, ...)     # 文件工具
    elif descriptor.kind == "general_skill":
        result = self._invoke_general_skill(...)             # 通用技能
    elif descriptor.kind == "knowledge":
        result = self._search_knowledge(...)                 # 知识检索
    elif descriptor.kind == "tool":
```

- `read_published_deliverable` — 读取历史交付物

### 6.5 逻辑动作回放

对于有副作用的工具（如 POST 请求），系统会计算逻辑动作 key 防止重复调用：

```python
def _logical_action_key(self, descriptor, arguments) -> str | None:
    if descriptor.kind != "tool":
        return None
    tool = self.db.get(Tool, descriptor.capability_id)
    configured, key_fields = ToolReplayPolicy.configuration(
        tool.config_json, tool.input_schema,
    )
    if configured is False:
        return None
    key_arguments = ToolReplayPolicy.arguments(arguments, key_fields)
    signature = ToolReplayPolicy.signature(tool.name, key_arguments)
    canonical = json.dumps({
        "tenant_id": self.tenant_id,
        "task_frame_id": self.task_frame_id,
        "step_id": self.active_step_id,
        "tool_id": tool.id,
        "signature": signature,
    }, sort_keys=True)
    return "sha256:" + hashlib.sha256(canonical.encode("utf-8")).hexdigest()

def _replay_or_block(self, logical_action_key) -> dict[str, Any] | None:
    prior = self.db.exec(
        select(HarnessInvocationRecord).where(
            HarnessInvocationRecord.logical_action_key == logical_action_key
        )
    ).first()
    if prior is None:
        return None  # 首次调用，继续执行
    if prior.status == "completed" and prior.response_cache_json.get("success") is True:
        return _replayed_result(prior)  # 重放成功结果
    return _failure("TOOL_CALL_OUTCOME_UNKNOWN", "相同副作用调用已有未完成的记录。")
```

### 6.6 大型结果持久化

当工具返回的 JSON 超过 2000 字符时，系统将其写入沙箱文件，避免撑爆模型上下文：

```python
_INLINE_JSON_TOOL_RESULT_MAX_CHARS = 2_000

def _persist_large_json_result(self, payload, *, call_id):
    data = payload.get("data")
    if not isinstance(data, (dict, list)):
        return payload
    serialized = json.dumps(data, ensure_ascii=False, separators=(",", ":"))
    if len(serialized) <= _INLINE_JSON_TOOL_RESULT_MAX_CHARS:
        return payload  # 小结果直接内联

    # 写入沙箱文件
    self._file_executor.execute(self._file_context, HarnessToolCall(
        call_id=f"{call_id}-result",
        name="write_file",
        arguments={
            "path": f".harness/tool-results/{call_id}.json",
            "content": serialized,
            "create_parents": True,
        },
    ))

    # 替换为文件引用
    payload["data"] = {
        "kind": "sandbox_json_file",
        "sandbox_path": f"/workspace/.harness/tool-results/{call_id}.json",
        "size": stored_data.get("size"),
        "sha256": stored_data.get("sha256"),
    }
    return payload
```

后续调用可以通过 `_resolve_json_tool_result_references()` 自动读取文件引用，将其还原为 JSON 数据。

### 7.1 工具可见性

### 7.2 技能级工具限制

工具可以通过 `allowed_skills_json` 限制只有特定技能才能调用：

```python
    active_skill_id
```

### 7.3 Secret 安全

- Secret 只从环境变量读取（`os.getenv()`）
- 正则模式 `${secret.NAME}` 只匹配大写字母和数字
- Secret 不会出现在审计日志中（`_audit_arguments()` 会脱敏）

```python
def _audit_arguments(arguments: dict[str, Any]) -> dict[str, Any]:
    audited = {}
    for key, value in arguments.items():
        lowered = str(key).lower()
        if any(token in lowered for token in ("content", "secret", "token", "password", "api_key")):
            audited[str(key)] = "<redacted>"
        else:
            audited[str(key)] = value
    return audited
```

### 7.5 超时控制

```python
def _execution_policy(self, tool, *, timeout_seconds_override=None) -> ToolExecutionPolicy:
    execution = (tool.config_json or {}).get("execution")
    raw_timeout = execution.get("timeout_seconds") if isinstance(execution, dict) else None
    try:
        timeout_seconds = float(raw_timeout)
    except (TypeError, ValueError):
        timeout_seconds = self.settings.tool_timeout_seconds
    # 限制范围 1-3600 秒
    if not 1 <= timeout_seconds <= 3600:
        timeout_seconds = self.settings.tool_timeout_seconds
    # 外部覆盖取较小值
    if timeout_seconds_override is not None:
        timeout_seconds = min(timeout_seconds, max(float(timeout_seconds_override), 0.1))
    return ToolExecutionPolicy(timeout_seconds=timeout_seconds)
```

## 8. 错误处理体系

### 8.1 统一错误码

| 错误码 | 含义 | 来源 |
|--------|------|------|
| `NOT_FOUND` | 工具不存在 | ToolExecutor |
| `DISABLED` | 工具未启用 | ToolExecutor |
| `NOT_ALLOWED` | 无权限 | ToolExecutor |
| `TIMEOUT` | 调用超时 | HTTP/MCP/A2A |
| `HTTP_ERROR` | HTTP 状态码异常 | HTTP |
| `MCP_ERROR` | MCP 协议错误 | MCP |
| `MCP_EXECUTION_ERROR` | MCP 执行异常 | MCP |
| `A2A_TIMEOUT` | A2A 任务超时 | A2A |
| `A2A_TASK_FAILED` | A2A 任务失败 | A2A |
| `CAPABILITY_NOT_ACTIVATED` | 能力未激活 | HarnessInvoker |
| `CAPABILITY_AUTHORIZATION_REVOKED` | 授权已撤销 | HarnessInvoker |
| `CAPABILITY_SNAPSHOT_CHANGED` | 快照已变更 | HarnessInvoker |
| `TOOL_CALL_OUTCOME_UNKNOWN` | 副作用结果未知 | HarnessInvoker |

### 8.2 调用状态机

```python
# HarnessInvocationRecord.status
"started"          # 开始调用
"completed"        # 成功完成
"failed"           # 配置/授权失败（可重试）
"outcome_unknown"  # 副作用已发生但结果未知（不可自动重试）
"cancelled"        # 执行被取消
```

`outcome_unknown` 的设计很关键：当 HTTP 超时或连接断开时，外部服务可能已经处理了请求。此时不能自动重试（避免重复副作用），需要人工核实。

## 9. 面试准备题

### Q1：三种工具类型（HTTP/MCP/A2A）的区别和适用场景是什么？

**答题要点**：
1. **HTTP**：最简单的 REST 调用，适合无状态的 API 调用（查天气、查数据库）
2. **MCP**：标准化协议，支持工具发现（`tools/list`）和分页，适合接入第三方工具服务器
3. **A2A**：有持久化 Task 生命周期，支持流式、恢复、取消，适合长时间运行的跨 Agent 任务

### Q2：Harness 的渐进式披露机制解决了什么问题？

**答题要点**：
1. **上下文窗口限制**：把所有工具的完整 schema 塞给 LLM 会浪费大量 token
2. **四步流程**：catalog（摘要列表）→ describe（加载 schema）→ activate（加入可用集）→ invoke（执行）
3. **安全收益**：只有经过 describe 的能力才能被 invoke，防止 LLM 调用"隐藏"的工具
4. **实现**：`_activated_names` 集合控制，`invoke()` 中检查 `name not in self._activated_names`

### Q3：如何防止工具的重复副作用调用？

**答题要点**：
1. `logical_action_key` 计算：基于 `(tenant_id, task_frame_id, step_id, tool_id, signature)` 的 SHA256
2. `_replay_or_block()`：查找已有记录，如果 `completed + success` 则重放结果
3. 如果前一次调用状态是 `outcome_unknown`，则阻止重试，要求人工核实
4. `ToolReplayPolicy` 控制哪些工具启用回放（默认 GET 不启用，POST 启用）

### Q4：MCP 协议的 stdio 和 HTTP 传输有什么区别？

**答题要点**：
1. **stdio**：启动本地子进程，通过 stdin/stdout 通信。适合本地工具（Node.js 脚本）
2. **HTTP（streamable_http）**：HTTP POST + JSON-RPC，支持 SSE 响应。适合远程服务器
3. **SSE**：旧版协议，GET 建立 SSE 流 + POST 发送请求
4. 核心区别：stdio 需要管理进程生命周期（启动/超时/退出码），HTTP 需要处理连接管理

### Q5：A2A 的持久化恢复机制是怎么工作的？

**答题要点**：
1. 每次 A2A 调用创建 `A2ATaskRun` 记录，持久化到数据库
2. 应用重启后，`recover_a2a_client_tasks()` 查找 `submitted`/`working` 状态的记录
3. 为每条记录启动独立线程，通过 `_resume_existing()` 恢复
4. 恢复时先检查远端 Task 状态（`GetTask`），如果已完成直接返回结果
5. 使用 `invocation_id` 做幂等键，防止重复创建 Task

### Q6：Secret 插值机制如何保证安全？

**答题要点**：
1. 只从环境变量读取（`os.getenv()`），不从数据库或用户输入获取
2. 正则模式 `${secret.[A-Z0-9_]+}` 只匹配大写字母+数字+下划线
3. 审计日志中自动脱敏（`_audit_arguments()` 将含 "secret"/"token" 等关键词的参数替换为 `<redacted>`）
4. Secret 解析发生在请求构建阶段，不会在日志中暴露明文

### Q7：大型工具结果为什么要持久化到文件？

**答题要点**：
1. **Token 成本**：知识检索可能返回数万字符，全部注入模型上下文会浪费大量 token
2. **阈值控制**：JSON 序列化后超过 2000 字符的结果写入沙箱文件
3. **引用机制**：模型收到 `{"kind": "sandbox_json_file", "sandbox_path": "..."}` 引用
4. **按需读取**：后续工具调用时，`_resolve_json_tool_result_references()` 自动解析引用
5. **安全校验**：读取引用时验证路径（必须在 `.harness/tool-results/` 目录下）、sha256 和大小

### Q8：工具调用的超时控制是如何设计的？

**答题要点**：
1. **三层超时**：工具配置 `config_json.execution.timeout_seconds` → 全局默认 `settings.tool_timeout_seconds` → 外部覆盖 `timeout_seconds_override`
2. **范围限制**：1-3600 秒，超出范围回退到默认值
3. **覆盖取小**：`timeout_seconds_override` 只取较小值，不能放大超时
4. **A2A 特殊处理**：有独立的 `a2a_task_timeout_seconds` 和 `a2a_poll_interval_seconds`
5. **步骤级超时**：`step_deadline_monotonic` 控制单个步骤的剩余时间
