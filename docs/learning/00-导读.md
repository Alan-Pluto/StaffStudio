# 导读：Staff Studio 学习指南

> 本文档面向即将使用 Staff Studio 作为求职项目 portfolio 的应届硕士毕业生，帮助你快速理解项目全貌、规划学习路径、并为技术面试做好准备。

---

## 1. 项目简介

### 1.1 什么是 Staff Studio（StaffDeck）

Staff Studio 是一套面向企业的**数字员工构建与管理平台**。它帮助专业员工将工作经验、业务流程和判断标准固化为可以持续工作的"数字员工"，让数字员工接手重复性任务，并将个人能力沉淀为**可复用、可迭代、可追溯**的组织资产。

简单来说：你可以用 Staff Studio 创建"会做事的 AI 助手"，它们有岗位、有工号、有能力档案、有工作记录，并且能持续成长。

### 1.2 开发团队

Staff Studio 由以下机构联合开发：

| 机构 | 说明 |
|------|------|
| **ModelBest** | 模型服务与企业 AI 解决方案提供商 |
| **NEU-ModelBest 联合实验室** | 东北大学与 ModelBest 的产学研联合实验室 |
| **THUNLP** | 清华大学自然语言处理实验室（Natural Language Processing Lab at Tsinghua） |
| **OpenBMB** | 开源大规模预训练模型社区，孵化了 CPB、MiniCPM 等知名模型 |
| **AI9Stars** | AI 应用落地与企业服务公司 |

项目由 [OpenBMB](https://www.openbmb.cn/) 生态孵化，采用 AGPL v3.0 开源协议。

### 1.3 平台核心能力

| 能力 | 说明 |
|------|------|
| **数字员工构建与管理** | 将员工的经验、流程和判断标准固化为拥有岗位、工号、能力档案和工作记录的数字员工；支持能力成长、权限隔离及发布复用 |
| **状态机驱动的流程型技能（SOP）** | 通过自然语言生成结构化 SOP，以状态机保证复杂流程准确执行；支持多流程实时切换、上下文保留、可视化编辑、版本管理和分支演化 |
| **文档结构感知的知识检索** | 基于文档、章节、页面和摘要等层级构建可导航索引，让数字员工先判断信息可能位于哪里，再逐层定位原文；支持知识分桶、定向检索、来源引用和检索调试 |
| **自主执行与持续迭代** | 通过 HTTP API、MCP 和定时任务执行真实业务操作，并结合长期记忆、完整 Trace、真人接管、用户反馈和反馈分析形成持续迭代闭环 |
| **IM 渠道集成** | 支持微信、企业微信、飞书、钉钉等主流即时通讯工具，用户可直接在 IM 中与数字员工对话 |

## 3. 学习路径建议

### 3.1 目标一：理解系统架构（适合后端/全栈方向）

建议阅读顺序：

1. **本文** → 建立整体认知
2. `01-项目概览与架构.md` → 深入理解分层设计
3. 阅读核心代码：
   - `backend/app/main.py` → 应用入口与路由注册
   - `backend/app/core/agent_loop.py` → Agent 执行主循环
   - `backend/app/core/harness_v2_engine.py` → Harness v2 执行引擎
   - `backend/app/core/turn_planner.py` → 任务规划器
4. 理解数据流：从用户消息到响应的完整链路
5. 阅读模块代码：`channels/`、`knowledge/`、`tools/`、`memory/` 等

### 3.2 目标二：准备技术面试（适合所有方向）

建议重点关注：

1. **架构设计**：单端口架构、分层设计、多租户隔离
2. **核心概念**：SOP 状态机、Harness 执行引擎、TaskFrame 任务帧
3. **数据模型**：40+ 张表的设计思路、前缀 ID 设计、JSON 列的灵活使用
4. **前端架构**：双 Shell 设计、状态管理策略、组件组织
5. **工程实践**：错误恢复、幂等性、会话租约、崩溃恢复

面试时可以重点展示：
- 如何设计一个支持多租户的 SaaS 平台
- 如何实现 SOP 状态机驱动的流程执行
- 如何设计可扩展的工具系统（HTTP/MCP/A2A）
- 如何实现 IM 渠道的适配器模式

### 3.3 目标三：快速上手开发（适合实习/入职准备）

建议操作顺序：

1. 按本文第 5 节搭建开发环境
2. 启动服务，体验完整功能
3. 阅读 `01-项目概览与架构.md` 了解代码组织
4. 尝试修改一个小功能（如 UI 文案、API 响应）
5. 阅读相关模块代码，理解修改的影响范围

## 5. 开发环境搭建

### 5.1 环境要求

- **操作系统**：macOS、Linux、WSL 或 Windows PowerShell
- **Python**：3.11 或更高版本
- **Node.js**：20.x 或更高版本
- **npm**：随 Node.js 安装
- **模型服务**：OpenAI Chat Completions 兼容接口 + API Key

### 5.2 安装步骤

#### 步骤 1：克隆仓库

```bash
git clone https://github.com/OpenBMB/StaffDeck.git
cd StaffDeck
```

#### 步骤 2：安装后端依赖

**macOS / Linux / WSL：**

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -e "backend[dev]"
```

**Windows PowerShell：**

```powershell
py -3 -m venv backend\.venv
.\backend\.venv\Scripts\python.exe -m pip install -e "backend[dev]"
```

#### 步骤 3：安装前端依赖

```bash
npm --prefix frontend-enterprise ci
```

#### 步骤 4：配置环境变量

```bash
cp backend/.env.example backend/.env
```

编辑 `backend/.env`，配置模型服务：

```dotenv
# 应用密钥（请替换为足够长的随机字符串）
APP_SECRET="your-secret-key-here"

# 模型服务配置（OpenAI 兼容接口）
DEMO_MODEL_BASE_URL="https://your-api-endpoint/v1"
DEMO_MODEL_NAME="your-model-name"
DEMO_MODEL_API_KEY="your-api-key"
```

> **注意**：API Key 用于创建初始模型配置，存入数据库前会被加密。请勿提交 `.env` 文件到版本库。

#### 步骤 5：启动开发服务

**macOS / Linux / WSL：**

```bash
scripts/dev_up.sh --detach
```

**Windows PowerShell：**

```powershell
.\scripts\dev_up.ps1 --detach
```

启动过程会：
1. 构建前端生产版本
2. 启动 FastAPI 服务，在 `5173` 端口同时提供 UI、API 与文档

#### 步骤 6：验证安装

```bash
curl http://127.0.0.1:5173/api/health
```

预期输出：

```json
{"status": "ok", "app": "Staff Studio"}
```

打开浏览器访问 [http://127.0.0.1:5173/workspace/gallery](http://127.0.0.1:5173/workspace/gallery)，使用默认管理员账号 `admin` / `admin` 登录。

### 5.3 常用命令

| 操作 | macOS / Linux / WSL | Windows PowerShell |
|------|---------------------|-------------------|
| 后台启动 | `scripts/dev_up.sh --detach` | `.\scripts\dev_up.ps1 --detach` |
| 前台启动 | `scripts/dev_up.sh` | `.\scripts\dev_up.ps1` |
| 查看状态 | `scripts/dev_status.sh` | `.\scripts\dev_status.ps1` |
| 停止服务 | `scripts/dev_down.sh` | `.\scripts\dev_down.ps1` |

### 5.4 运行测试

**后端测试：**

```bash
backend/.venv/bin/python -m pytest backend/tests
```

**后端代码检查：**

```bash
backend/.venv/bin/ruff check backend
```

**前端测试：**

```bash
npm --prefix frontend-enterprise test
```

**前端构建（含类型检查）：**

```bash
npm --prefix frontend-enterprise run build
```
